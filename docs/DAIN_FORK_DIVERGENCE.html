How it accumulated

The flagship: what happens on a rate limit

Upstream answers a 429 by downgrading the model, so a spent Opus window silently becomes Sonnet output. Ours keeps the model and changes the account, and only leaves the model behind when no account anywhere has credit.

Where the code went

Every group

1. Anthropic account-first failover

21 files · +5,548 / -32740 commitsADR 0001-0024

Upstream answers a rate limit by downgrading the model. Ours tries the same model on the next OAuth account first.

  • Rotate the account inside the streaming retry loop, on an in-stream 429, not only at request setup.
  • Remember a rate-limited account across requests, so a later call does not walk back into the same wall.
  • Exhaustion is any spent window, five-hour or seven-day, pinned as one verdict rather than three private copies of the rule.
  • Serialise rotation across concurrent sessions; never restore a dead-end override onto a quota-blocked account.
  • Retry capacity rejections on their own budget and clock, separate from the rate-limit path.
  • Broadcast anthropic_account_rotated on the bus, forward it through the server, follow it in the TUI, and name the active account in the header, status bar and side widget.

8. Prompt queue

Governs mid-turn routing and skill prompts. A prompt the server rejects as busy is queued rather than lost, and is not redispatched on every progress event.

10. Skill frontmatter opt-out

15. Uncommitted in the tree

17 files · +589 / -64not in any commit

Absent from every git log based summary, so easy to under-report.

  • Exhaustion generalised beyond Claude: one per-account probe for every provider, so a spent OpenAI account is finally recognised as spent.
  • A rate limit must not be answered with the same model on the same provider's other credential. On a subscription provider that is usually the same account behind a different door, and it silently moves you onto metered billing. Deprioritised, never removed.
  • Route exhaustion is remembered per turn, ending a Claude to OpenAI to Claude ping-pong that ran about once a second and never terminated.
  • Larger stop-word list for task labels, a macOS bash-3.2 prompt section, an agentgrep suppression note, and a new remote-events test.

What a rebase will cost

Porting this to the Pi harness

Pi is a TypeScript monorepo at ~/MYNE/Projects/tools/pi, ten packages under packages/. Everything below was checked against that checkout on 2026-09-01, not assumed from the feature names.

One blocker sits under everything else. Pi's credential store is documented as keyed by provider id, one credential per provider, and the word "account" does not appear in it at all. Our flagship feature has nowhere to live until that type changes.

The blocker, in Pi's own words

ai/src/auth/types.ts:40CredentialInfo is {providerId, type}. No account identity anywhere in it.

Credential and CredentialStore are exported from @earendil-works/pi-ai, a published package. Changing their shape is not an internal refactor.
